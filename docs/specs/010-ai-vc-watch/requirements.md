# 010 — 需求

## 背景与目标

用户希望持续跟踪 AI 领域「新内容、新产品、热门投资」三类信息。其中**热门投资（融资事件）是结构化数据**，最适合沉淀进工作台：把分散在 TechCrunch、HN、IT桔子、公众号等渠道的 AI 融资事件统一收进 SQLite，**先积累（存量回填 + 增量更新），再可视化分析**。

本 spec 目标：新增工作台第三个一级板块「AI 创投观察」，提供——

1. **融资事件流**：按时间排序的公司融资记录（公司 / 轮次 / 金额 / 赛道 / 来源 / 链接），支持过滤。
2. **数据管道**：英文源（TechCrunch Venture RSS + Hacker News Algolia）自动化抓取，幂等入库；中文源因反爬实测不可程序化抓取，提供**人工录入**通道补足。
3. **可视化分析**：赛道分布、月度融资趋势等聚合图 —— 为后续深入分析积累数据地基。

## 用户故事

### US-1 板块骨架与导航

作为使用者，我在侧边栏看到「AI 创投观察」这一新的一级板块，点进去后用顶部二级菜单在「事件流 / 分析」间切换 —— 与「宏观经济」「资产行情」的操作方式保持一致。

- **AC1**: 侧边栏一级菜单在「资产行情」之后新增「AI 创投观察」，指向 `/ai-vc`；路径为 `/ai-vc` 或子页时该项均判定为激活态。
- **AC2**: 进入该板块后顶部渲染二级菜单，与既有板块同源组件（`SectionTabs`），视觉与交互一致。
- **AC3**: 子页共用一个路由组布局（`src/app/(vc)/layout.tsx`），各页不各自渲染 Topbar 与滚动容器。
- **AC4**: 侧边栏一级菜单最终为「工作台 / 宏观经济 / 资产行情 / AI 创投观察 / 设置」五项。
- **AC5**: 首页新增「AI 创投观察」模块卡片，展示库内事件总数与最新事件日期，可点击进入。

### US-2 融资事件流

作为使用者，我能看到按时间倒序排列的 AI 融资事件列表，快速了解「谁、什么时候、融了多少钱、什么轮次、属于什么赛道」。

- **AC1**: `/ai-vc` 首屏渲染事件列表（默认按公告日期倒序），每行展示：公告日期、公司、轮次、金额、赛道、来源徽标、原文链接。
- **AC2**: 金额统一折算为美元展示（原币种金额与汇率近似换算口径在 tooltip 标注）；未披露金额显示「未披露」，不得显示 0 或占位数。
- **AC3**: 支持按赛道、按来源过滤；支持「仅看有大额事件」等便捷筛选（阈值可配置，默认 ≥ $10M）。
- **AC4**: 列表分页或懒加载，单页不超过 50 条，长列表不卡顿。
- **AC5**: 顶部展示统计摘要：事件总数、本月新增、金额合计（近 90 天，未披露不计入）。

### US-3 数据管道与增量更新

作为使用者，我点一下按钮就能把英文融资事件更新到最新，看到进度、不会重复触发；首次运行能回填存量历史。

- **AC1**: `npm run fetch:vc` 可独立执行抓取；页面「更新数据」按钮触发同一管道（复用 spec 003 交互模型）。
- **AC2**: 抓取过程输出逐来源进度（当前/总数 + 来源名 + 结果），前端以进度条呈现。
- **AC3**: 抓取运行期间按钮禁用，重复触发返回 `409`；状态查询接口与既有板块同构。
- **AC4**: 抓取**幂等**：连续执行两次，`deal_event` 表行数与内容完全一致（`INSERT OR REPLACE`，去重键 `(source, source_id)`）。
- **AC5**: 单来源抓取失败不中断整体流程，失败来源记录在最终汇总中，其余来源正常入库。
- **AC6**: **存量回填**：首次运行 `fetch:vc` 时，HN 源按 `numericFilters` 回填最近 90 天的相关条目；TechCrunch RSS 仅能取到最近条目（RSS 无长历史，如实记录在「数据新鲜度」中）。
- **AC7**: 去重：同一公司同一轮次（同 `source_id` 或同 URL）重复出现时只保留一条。

### US-4 人工录入（中文源补充）

作为使用者，我在 IT桔子 / 烯牛 / 公众号看到中文融资事件时，能手动录入一条入库，补充自动化管道覆盖不到的中文事件。

- **AC1**: 「新增事件」入口（事件流页按钮或独立表单页），字段：公司（必填）、公告日期（必填，`YYYY-MM-DD`）、轮次（预置枚举或自定义）、金额与币种（可空 = 未披露）、赛道（预置列表或自动分类建议）、原文链接（可选）、备注（可选）。
- **AC2**: 提交校验：公司与日期必填、日期格式非法 / 金额非法时返回字段级错误，不得静默丢弃。
- **AC3**: 录入的 `source` 为 `manual`；同 URL 已存在时提示重复（返回 409），但允许用户选择「仍要新增」（覆盖场景：同公司多轮次同一新闻链接）。
- **AC4**: 录入成功后事件立即出现在事件流中（写入实时可见）。

### US-5 可视化分析

作为使用者，我能看到融资数据在赛道、时间两个维度上的聚合视图，为投资观察提供直观依据。

- **AC1**: `/ai-vc/analytics` 渲染**赛道分布图**（按事件数或金额合计，饼图或横向柱），点击图例可切换口径（计数 / 金额）。
- **AC2**: 渲染**月度融资趋势图**（近 12 个月，柱 = 事件数，线 = 金额合计，双轴），未披露金额不计入金额线。
- **AC3**: 两张图支持按来源、按赛道过滤联动；空数据时显示「暂无数据」占位而非空白图。
- **AC4**: 图表下方注明聚合口径（如「金额 = 已披露事件的 amount_usd 合计」）。

### US-6 数据新鲜度

作为使用者，我要知道融资事件数据更新到什么时候，判断是否需要手动更新。

- **AC1**: 事件流页顶部展示「最新事件日期」与「最近一次抓取时间」（`deal_event.updated_at` 最大值）。
- **AC2**: 超过 3 天未更新（抓取时间）时标注 amber 提示「数据可能滞后」。
- **AC3**: 事件流页展示各来源的数据覆盖说明（如「TechCrunch：最近条目；HN：近 90 天；手动：用户录入」），避免用户误以为覆盖全历史。

## 验收补充

- **AC-A**: `npm test` 全绿。新增断言覆盖**纯函数契约**：金额解析（`$10M` / `€40M` / `£1.2B` / 未披露 / 中文「亿元」）、轮次归一化（`Series A` → `A`）、赛道分类关键词（基础设施 / 大模型 / 应用 / 具身智能等）、去重键构造、月度分组键。
- **AC-B**: `next build` 通过。
- **AC-C**: 页面实测：`/ai-vc` 与 `/ai-vc/analytics` 均 200，侧边栏「AI 创投观察」高亮正确。
- **AC-D**: 抓取实测：`npm run fetch:vc` 后 `data/vc.db` 中存在事件，`latest_date` 与源最新一致；连续执行两次行数不变（幂等）。
- **AC-E**: 人工录入实测：提交一条合法事件后出现在事件流；提交非法日期 / 空公司被拒绝并返回字段错误。
