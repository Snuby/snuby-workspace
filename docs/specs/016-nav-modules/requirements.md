# Spec 016 — 需求（requirements）

## 1. 功能需求

### FR-1 榜单页顶条移除（✅ 已完成）
- 去掉「内容跟随官方页面实时更新；交互与滚动在框架内进行。」提示行与「在新窗口打开 ↗」链接。
- 桌面版与 Web 版共用组件（`webview-frame.tsx`），改一处两版同时生效。
- 提交 `d6ef31d`（spec 016 第 1 项）。

### FR-2 IT 资讯模块
- 左侧一级菜单「IT 资讯」，收录权威专业 IT 媒体站。
- 桌面版：内嵌 webview 打开媒体官网；Web 版：降级（见 FR-5）。
- 收录哪些媒体 = **决策点 D1**（候选清单见 §3）。

### FR-3 自媒体模块
- 左侧一级菜单「自媒体」，包含两个入口：小红书创作中心、微信公众号后台。
- 桌面版：webview 内嵌官网；登录二维码/验证码在 webview 内展示，用户手机扫码完成。
- 登录态处理 = **决策点 D3**。

### FR-4 Web 访问模块
- 左侧一级菜单「Web 访问」，顶部地址栏自填 URL + 简易浏览器（前进/后退/刷新/主页）。
- 默认主页 = **决策点 D4**。
- Web 版处理 = **决策点 D5**。

### FR-5 三模块的 Web 版（非 Electron）降级
- Web 版没有 `<webview>`（Electron 专有元素），候选方案：
  - A. 隐藏 Web 访问入口（浏览器功能仅桌面版有意义），IT 资讯/自媒体用 iframe 尽力渲染或新窗口外链
  - B. 三模块 Web 版一律显示「请使用桌面版」提示页
  - C. 全部用 iframe + 新窗口外链（受 XFO/CSP 限制，可靠性差，不推荐）
  - **推荐 A**：Web 访问隐藏（或提示页），IT 资讯/自媒体 iframe+外链尽力渲染。

## 2. 非功能需求

- **NFR-1 安全**：延续 013/015 定案——webview 默认放行所有导航、`window.open` allow、webview 权限全拒（`main.js` 现状），三模块不引入新拦截。
- **NFR-2 持久化**：自媒体登录态（若采用 D3 持久化）存 `userData` 下的持久 session 分区，重启保留；不污染主 session。
- **NFR-3 一致性**：侧边栏、Topbar、SectionTabs、首页卡片沿用现有样式与结构惯例。
- **NFR-4 测试**：新增组件/单元测试随实现补齐，全量测试保持全绿（当前 106 例）。
