# Spec 016 — 需求（requirements）

## 1. 功能需求

### FR-1 榜单页顶条移除（✅ 已完成）
- 去掉「内容跟随官方页面实时更新；交互与滚动在框架内进行。」提示行与「在新窗口打开 ↗」链接。
- 桌面版与 Web 版共用组件（`webview-frame.tsx`），改一处两版同时生效。
- 提交 `d6ef31d`（spec 016 第 1 项）。

### FR-2 IT 资讯模块
- 左侧一级菜单「IT 资讯」，收录权威专业 IT 媒体站。
- **交互形态（决策点 D2 已批复，2026-09-23）**：选项卡形式（视觉与 AI 模型榜单的 SectionTabs 一致），**支持用户动态添加/删除媒体**。
- 桌面版：webview 内嵌媒体官网；Web 版：降级（见 FR-5）。
- 收录哪些媒体：内置默认推荐集（D1，见 §3），自定义媒体由用户动态添加。

### FR-3 自媒体模块
- 左侧一级菜单「自媒体」，包含两个入口：小红书创作中心、微信公众号后台。
- 桌面版：webview 内嵌官网；登录二维码/验证码在 webview 内展示，用户手机扫码完成。
- 登录态处理（D3 推荐：持久化到 userData session 分区）。

### FR-4 Web 访问模块
- 左侧一级菜单「Web 访问」，顶部地址栏自填 URL + 简易浏览器（前进/后退/刷新/主页）。
- **默认主页（D4 已批复，2026-09-23）**：Google（`https://www.google.com`）。
- Web 版处理：见 FR-5。

### FR-5 三模块的 Web 版（非 Electron）降级
- **降级语义**：Web 版（浏览器里打开的网页版）没有 Electron 的 `<webview>` 元素，内嵌能力只剩两种：
  - **iframe**：把媒体官网嵌进当前页面——受目标网站的 `X-Frame-Options` / CSP 限制（榜单里 AA 能嵌、OR 拒绝嵌，正是这个原因），能嵌的正常显示，不能嵌的白屏。
  - **外链**：iframe 嵌不进去的，退化为「在新窗口打开」按钮/链接，直接在浏览器新标签打开官网。
- **各模块处理（D5 推荐 A，已按推荐执行）**：
  - IT 资讯：选项卡照常显示；Web 版打开媒体时 iframe 尽力渲染，被拒则提供外链按钮。
  - 自媒体：直接外链（登录页无内嵌价值）。
  - Web 访问：Web 版自己就是浏览器，该模块无意义 → 侧边栏隐藏入口；直连路由显示「请使用桌面版」提示页。

## 2. 非功能需求

- **NFR-1 安全**：延续 013/015 定案——webview 默认放行所有导航、`window.open` allow、webview 权限全拒（`main.js` 现状），三模块不引入新拦截。
- **NFR-2 持久化**：自媒体登录态（若采用 D3 持久化）存 `userData` 下的持久 session 分区，重启保留；不污染主 session。
- **NFR-3 一致性**：侧边栏、Topbar、SectionTabs、首页卡片沿用现有样式与结构惯例。
- **NFR-4 测试**：新增组件/单元测试随实现补齐，全量测试保持全绿（当前 106 例）。
