# Spec 017 — 需求（AgentSession 对象化架构）

## 用户故事

1. 作为工作台用户，我在两个会话里同时派发任务，切来切去看进度——**两个任务的输出、工具记录、产物绝不能混进对方的会话**（现状曾串台：2yom 会话写入了 w62l 的 messages.jsonl 与 artifacts）。
2. 作为工作台用户，我切走再切回一个会话，希望**立即看到之前的聊天内容**，不要重新加载转圈、不要白屏；正在跑的任务切走不中断、切回继续渲染。
3. 作为工作台用户，我切换模型/配置，只影响**当前会话**；切到另一个会话看到的模型、用量、连接信息是那个会话自己的。
4. 作为工作台用户，会话历史、产物落盘位置与组织方式稳定可预期：每个会话一个目录，内部数据与工作产物分开。
5. 作为工作台用户，我在会话 A 任务进行中切换到 B、新建 C、或重连网关——**这些操作不得把 A 的输出/产物写进 B/C，也不得在未对齐时对网关发 prompt**（操作边界见 design.md §11）。
6. 作为工作台用户，我点击停止后，界面立刻停下；我理解网关可能仍在收尾，且在收尾完成前新任务会排队而非真正并发。

## 验收标准

- **AC-1 文件隔离**：会话 A 任务执行期间/之后，会话 B 目录（`agent-sessions/<id>`）不得出现新写入；出现即被「越界审计」检出并在 UI 显示警告条。
- **AC-2 产物归位**：新建会话的网关 cwd 指向 `~/snuby-workspace-data/agent-sessions/<id>`（或 `AGENT_SESSIONS_PATH`）；任务产物写入 `<sessions>/<id>/artifacts/`。
- **AC-3 视图缓存**：同一会话切走再切回，不重新 fetch 消息（无 loading 闪烁），消息、分页游标、滚动位置语义保留；内存中最多保留 `UI_CACHE_MAX`（10）个会话视图，超出按 LRU 淘汰最久未用，**运行中的会话不淘汰**。
- **AC-4 status 拆分**：顶栏相位/网关进程/心跳来自全局 `status`；模型下拉、配置项、用量、连接 ID、ACP 会话 ID 来自当前会话的 `status?sid=`；切会话后这些值跟随切换，互不串。
- **AC-5 切换不中断**：会话 A 任务进行中切到会话 B、再切回 A，A 的流式输出继续且不回退；多会话任务经全局队列串行时，输出按 sessionId 落入各自缓存，仅激活会话同步渲染（**不要求网关侧真并行**）。
- **AC-6 迁移幂等**：重复启动不重复迁移、不丢文件；迁移失败不影响会话运行。
- **AC-7 切换零网关**：纯切换会话不触发 `session/load|new|prompt`；网关对齐仅发生在发送/显式激活/改配置等持锁操作。
- **AC-8 重连失效绑定**：ACP 重连后，旧连接上的运行中任务标 interrupted；各会话在下一次发送前重新对齐；不静默重放未完成 prompt。
- **AC-9 删除拦截**：running / queued / draining 中的会话不可直接删除；须先取消/停止并收尾。
- **AC-10 排队可取消**：他会话占用全局锁时，本会话发送进入排队并可取消；轮到已取消项则跳过。

## 非目标

- delegateToolsSupport 硬隔离（待协议验证；initialize 已声明 `delegateToolsSupport: true`，另开迭代）。
- 多账号 partition。
- 独立浏览器 Web 版（产品已定为仅 APP）。
- 承诺 `session/cancel` 必定终止网关侧任务或必定无残流（复测未稳定证实）。
