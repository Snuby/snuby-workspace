# Spec 017 — 需求（AgentSession 对象化架构）

## 用户故事

1. 作为工作台用户，我在两个会话里同时派发任务，切来切去看进度——**两个任务的输出、工具记录、产物绝不能混进对方的会话**（现状曾串台：2yom 会话写入了 w62l 的 messages.jsonl 与 artifacts）。
2. 作为工作台用户，我切走再切回一个会话，希望**立即看到之前的聊天内容**，不要重新加载转圈、不要白屏；正在跑的任务切走不中断、切回继续渲染。
3. 作为工作台用户，我切换模型/配置，只影响**当前会话**；切到另一个会话看到的模型、用量、连接信息是那个会话自己的。
4. 作为工作台用户，会话历史、产物落盘位置与组织方式稳定可预期：每个会话一个目录，内部数据与工作产物分开。

## 验收标准

- **AC-1 文件隔离**：会话 A 任务执行期间/之后，会话 B 目录（sessions 与 workspaces）不得出现新写入；出现即被「越界审计」检出并在 UI 显示警告条。
- **AC-2 产物归位**：新建会话的网关 cwd 指向 `data/agent-workspaces/<id>`；任务产物写入 `<workspaces>/<id>/artifacts/`；历史会话存量产物已迁移（旧 `sessions/<id>/artifacts` 清空，`meta.acpCwd` 指向新工作区）。
- **AC-3 视图缓存**：同一会话切走再切回，不重新 fetch 消息（无 loading 闪烁），消息、分页游标、滚动位置语义保留；内存中最多保留 `UI_CACHE_MAX`（10）个会话视图，超出按 LRU 淘汰最久未用，**运行中的会话不淘汰**。
- **AC-4 status 拆分**：顶栏相位/网关进程/心跳来自全局 `status`；模型下拉、配置项、用量、连接 ID、ACP 会话 ID 来自当前会话的 `status?sid=`；切会话后这些值跟随切换，互不串。
- **AC-5 并发不中断**：会话 A 任务进行中切到会话 B、再切回 A，A 的流式输出继续且不回退；两个任务并行时输出互不覆盖（commitMsgs 按 sessionId 落缓存，仅激活会话同步渲染）。
- **AC-6 迁移幂等**：重复启动不重复迁移、不丢文件；迁移失败不影响会话运行。
