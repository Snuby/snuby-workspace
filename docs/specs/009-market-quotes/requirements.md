# 009 — 需求

## 用户故事

### US-1 板块骨架与导航

作为使用者，我在侧边栏看到「资产行情」这一新的一级板块，点进去后用顶部二级菜单在各资产类别间切换 —— 与「宏观经济」的操作方式保持一致。

- **AC1**: 侧边栏一级菜单在「宏观经济」之后新增「资产行情」，指向 `/market`；路径为 `/market` 或任一子页时该项均判定为激活态。
- **AC2**: 进入该板块后顶部渲染二级菜单，与「宏观经济」的二级菜单组件同源（同一组件，非另写一套），视觉与交互一致。
- **AC3**: 五个子页共用一个路由组布局（`src/app/(market)/layout.tsx`），各页不各自渲染 Topbar 与滚动容器。
- **AC4**: 侧边栏一级菜单最终为「工作台 / 宏观经济 / 资产行情 / 设置」四项。
- **AC5**: 首页新增「资产行情」模块卡片，展示资产数量与数据最新日期，可点击进入。

### US-2 单资产 K 线

作为使用者，我能看到每个资产的蜡烛图，可切换日/周/月/年粒度。

- **AC1**: 11 个资产全部可展示 K 线，按类别归入对应子页（贵金属 2 / 加密货币 3 / 股票指数 4 / 房产 2）。
- **AC2**: 图上有日/周/月/年四档粒度切换，切换后**同一资产**重新聚合展示，不重新请求数据库。
- **AC3**: 蜡烛图展示 OHLC 四价，带十字光标（`axisPointer`）与缩放（`dataZoom`），可横向拖拽查看历史。
- **AC4**: 有成交量的资产（加密、美股、港股、A 股）在图下方渲染成交量柱副图；成交量不可用的资产（贵金属、房产）不渲染副图，不留空白区块。
- **AC5**: 蜡烛遵循**中国习惯：涨红跌绿**。配色以 `--color-up` / `--color-down` token 表达（新增 token，见 design 决策 9）。
- **AC6**: 每个资产卡展示最新价、当日涨跌幅、所选周期内的区间涨跌幅与最新数据日期。
- **AC7**: 数值展示精度按资产独立配置（`asset.precision`）：狗狗币 4 位小数、比特币/指数 2 位、房价 1 位 —— 不做全局统一格式化。

### US-3 降级：月频且无 OHLC 的资产

作为使用者，我看房价时不应被假装成 K 线的图形误导。

- **AC1**: `base_freq = 'M'` 的资产（北京 / 上海房价）在粒度切换器中**禁用「日」「周」两档**（置灰并给出原因 tooltip），仅「月」「年」可选。
- **AC2**: 无 OHLC 的资产（`has_ohlc = 0`）自动渲染为**折线图**而非蜡烛图，并在卡片上标注数据性质（如「统计口径：70 城二手住宅价格指数，非成交均价」）。
- **AC3**: 数据源时效与「统计口径」两类提示在 UI 上视觉可区分：前者是滞后警告（amber），后者是口径说明（ink-faint 中性色）。

### US-4 跨资产归一化合并图（核心）

作为使用者，我能把任意多个资产叠加到一张图上，直观看出谁涨得多、谁跌得惨。

- **AC1**: `/market` 首屏即渲染合并对比图，默认勾选一个覆盖面广的代表性子集（建议：黄金 / 比特币 / 上证 / 纳斯达克 / 北京房价），而非默认全选 11 个（避免线过密）。
- **AC2**: 提供资产勾选器，可任意增减；至少保留 1 个，最多 11 个。
- **AC3**: Y 轴为归一化值，基准点 = 100，起点值恒为 100（无论所选周期与窗口）。
- **AC4**: 支持自定义基准日：默认「区间起点」，可选「指定日期」（如 2020-01-01 = 100）。切换后所有曲线重算。
- **AC5**: 粒度随全局周期切换器（日/周/月/年）联动。
- **AC6**: 日期轴取所有已选资产日期的**并集**，缺失值**前向填充**（carry-forward），并在图上注明该对齐策略。
- **AC7**: 某资产在基准日尚无数据时（如比特币 2015 年不存在），该曲线从**其自身首个有数据点**开始，起点同样归一化为 100，且图例中标注其起始日期 —— 不允许用回填值伪造历史。
- **AC8**: 图例可点击切换单条曲线的显隐；被隐藏的曲线不参与 hover 联动提示。
- **AC9**: 图上提供时间窗口选择（近 1 年 / 3 年 / 5 年 / 全部），默认近 5 年。

### US-5 数据管道与增量更新

作为使用者，我点一下按钮就能把 11 个资产的数据更新到最新，且能看到进度、不会重复触发。

- **AC1**: `npm run fetch:market` 可独立执行抓取；页面「更新数据」按钮触发同一管道。
- **AC2**: 抓取过程输出逐资产进度（当前/总数 + 资产名 + 结果），前端以进度条呈现，与宏观板块的交互一致。
- **AC3**: 抓取运行期间按钮禁用，重复触发返回 `409`；状态查询接口与宏观板块同构。
- **AC4**: 抓取**幂等**：连续执行两次，`kline` 表行数与内容完全一致（`INSERT OR REPLACE`）。
- **AC5**: 单资产抓取失败不中断整体流程，失败资产记录在最终汇总中，其余资产正常入库。
- **AC6**: 增量策略明确：默认**全量拉取 + 幂等 upsert**；库中已有数据的资产，其 `last_date` 作为增量起点提示（详见 design 决策 8）。

### US-6 数据新鲜度

作为使用者，我要知道每个资产的数据截止到什么时候，以及是否已经该更新了。

- **AC1**: 每个资产卡展示「数据截至 YYYY-MM-DD」。
- **AC2**: 超过容忍阈值的资产标注滞后提示：日频资产以**自然日**计容忍（默认 5 天），月频资产以**月**计（默认 45 天）。
- **AC3**: 页面顶部展示最近一次抓取时间（`asset.updated_at` 的最大值）。

- **AC-B**: `next build` 通过。
